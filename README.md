# csolve-go

`csolve-go` восстанавливает распределение частиц по размерам
`n(r) = dV/dln r` из набора лидарных коэффициентов — обратного рассеяния `β`
и/или ослабления `α` — решая обратную задачу регуляризованным методом
наименьших квадратов с базисом из B-сплайнов.

Ядра задачи (сечения `Cext(x)` и `Cback(x)` как функции параметра размера
`x = 2πr/λ`) берутся из **внешних таблиц**, поэтому программа не выполняет
Mie-расчёт: спектр комплексного показателя преломления и форма частиц
«зашиты» в таблицы. Дополнительно, если в таблицах есть столбцы `S11`/`S22`,
считается линейная деполяризация обратного рассеяния `δ_l`.

Это порт табличного режима C-версии `csolve` на **Go 1.24**: численный
конвейер (сплайны, B-сплайны, квадратуры Гаусса–Лежандра, регуляризованный
МНК, перебор окон, ансамбль решений, сглаживание, моменты, модальный анализ)
повторяет C-версию, а линейная алгебра (SVD/МНК) выполнена через `gonum`.
Графики по умолчанию рисуются встроенным рендерером в PDF (чистый Go, без
внешних программ); прежняя отрисовка через **gnuplot** доступна по
`--plotting=gnuplot`.

## Возможности

- Восстановление `dV/dln r` по произвольному набору каналов `β`/`α`
  (до 32 каналов в JSON-входе), с единой моделью по всем каналам.
- Три встроенных набора таблиц сечений (`--type=sphere|spheroid|agglomerate`),
  сжатых и скомпилированных в бинарник; внешние таблицы — через `--tables`.
- Оценка комплексного показателя преломления `m = Re(m) + i·Im(m)` перебором
  доступных в таблицах значений.
- Автоматический выбор окна `[r0, r1]`, степени B-сплайна и параметра
  регуляризации `γ`.
- Ансамблевое усреднение лучших решений, сглаживание среднего,
  интегральные моменты (концентрации, `r_eff`) и логнормальные моды
  (fine/coarse/overall).
- Линейная деполяризация `δ_l` на 355 и 532 нм — если в таблицах есть
  `S11`/`S22`; опциональный учёт измеренного `δ_l` в функционале или при
  ранжировании (`--depol-ratio-cons`).
- Пакетная обработка профилей по высотам, включая ограничение гладкости
  лидарного отношения `S = α/β` вдоль высоты.
- Вывод в консоль, JSON и текстовые файлы; графики в PNG/PDF/SVG.

## Физическая постановка

Для каждого канала `j` (длина волны `λ_j`, тип `β` или `α`) измеренный
коэффициент выражается через распределение по объёму:

```
g_j = ∫ K_j(r) · q(r) · n(r) dr,      q(r) = 3 / (4π r⁴)
```

где `n(r) = dV/dln r`, а ядро `K_j(r)` — сечение из таблицы, пересчитанное
на нужную длину волны:

```
K_j(r) = C(x) · 1e-12 · (λ_j / λ_ref)²,      x = 2πr / λ_j
```

- `C(x)` — `Cext` для канала `α` и `Cback` для канала `β`;
- `λ_ref` — длина волны, при которой построены таблицы
  (`--table-ref-lambda-um`, по умолчанию `2π` мкм);
- множитель `1e-12` переводит мкм² в м²;
- для таблиц в конвенции `Cback = 4π·dσ/dΩ` укажите `--table-cback 4pi`
  (тогда `Cback` делится на `4π`).

Из таблиц также берётся допустимый диапазон `x`; он ограничивает сверху
максимальный радиус `r_max = x_max·λ/(2π)` для каждого канала.

Распределение раскладывается по B-сплайнам степени `p` на отрезке `[r0, r1]`
(по умолчанию с краевыми условиями `n(r0) = n(r1) = 0`), а коэффициенты
разложения находятся из регуляризованной системы

```
min ‖ W (A c − g) ‖² + γ² ‖ L c ‖²,
A[j,i] = ∫ K_j(r) q(r) B_i(r) dr,
```

где `L` — матрица вторых разностей (штраф за кривизну решения),
`W` — веса невязок. При `--depol-ratio-cons --depol-ratio-mode func` в
систему добавляется линейное ограничение по измеренному `δ_l` (см. раздел
опций); в режиме `rank` ограничение применяется при сортировке вариантов.
Все варианты `(m, r0, r1, degree)` перебираются, сортируются по средней
относительной ошибке `Err` и усредняются.

## Требования и сборка

Требования:

- **Go 1.24** (модуль объявляет `go 1.24.0`);
- `gonum` (`gonum.org/v1/gonum`, подтягивается через `go.sum`), cgo не нужен;
- `gonum.org/v1/plot` — встроенный рендерер PDF (тоже чистый Go);
  шрифт DejaVu Sans (`codeberg.org/go-fonts/dejavu`) встроен в бинарник;
- **gnuplot** в `PATH` — только при `--plotting=gnuplot`; по умолчанию
  (`--plotting=internal`) gnuplot не требуется.

Сборка:

```bash
cd csolve-go
make                # -> ./csolve
make build-windows  # -> ./csolve.exe (Windows x86_64)
make test           # юнит-тесты (внешние таблицы не нужны)
make vet
make generate       # пересобрать .gz встроенных таблиц (после правки bases/)
make clean          # удалить бинарники
```

Напрямую:

```bash
go build -trimpath -o csolve ./cmd/csolve
go test ./...
```

Кросс-сборка под Windows с macOS/Linux:

```bash
GOOS=windows GOARCH=amd64 go build -trimpath -o csolve.exe ./cmd/csolve
```

На Windows:

```bat
go build -trimpath -o csolve.exe .\cmd\csolve
```

## Быстрый старт

Полная справка по флагам:

```bash
./csolve --help
```

Демонстрация на синтетических данных (входные коэффициенты считаются прямой
задачей по двум логнормальным модам; каналы `β` 355/532/1064 нм и `α`
355/532 нм) — если `--data` не указан. Таблицы встроены в бинарник, поэтому
`--tables` не обязателен:

```bash
./csolve --type=sphere --table-extrapolate \
         --r0-min 0.05 --r0-max 0.3 --r1-min 0.5 --r1-max 1.9 --no-plot
```

Восстановление по собственным измерениям из JSON с сохранением результата:

```bash
./csolve --data input.json --type=sphere --table-extrapolate \
         --r0-min 0.05 --r0-max 0.3 --r1-min 0.5 --r1-max 1.9 \
         --json out.json
```

Встроенный набор агрегатов — дополнительно считается `δ_l`
(здесь `δ_l ≈ 1.67 %` и `0.64 %` на 355 и 532 нм):

```bash
./csolve --type=agglomerate --table-extrapolate \
         --r1-min 0.1 --r1-max 0.6 --no-plot
```

Внешние таблицы (не входящие в бинарник) задаются через `--tables` — путь
указывает на каталог **с подкаталогами `mre_*`**:

```bash
./csolve --tables bases/large_aggl_100/shape02 --table-extrapolate \
         --r1-min 0.1 --r1-max 0.6 --no-plot
```

Одна степень B-сплайна (в отличие от C-версии, `--degree` принимает ровно
одно значение):

```bash
./csolve --type=sphere --table-extrapolate --degree 3 --no-plot
```

Пакетная обработка по высотам с ограничением гладкости `S = α/β`:

```bash
./csolve --batch measurements.txt --batch-out-dir out_batch \
         --type=sphere --table-extrapolate \
         --r0-min 0.05 --r0-max 0.3 --r1-min 0.5 --r1-max 1.9 \
         --lidar-ratio-cons
```

Учёт измеренной деполяризации `δ_l` (столбец `dep<nm>` в TXT или группа
`depolarization` в JSON). По умолчанию ограничение добавляется в функционал
(`--depol-ratio-mode func`), прежнее поведение `main` — штраф при
ранжировании (`--depol-ratio-mode rank`):

```bash
./csolve --batch measurements.txt --batch-out-dir out_batch \
         --depol-ratio-cons --lidar-ratio-cons          # в TXT есть dep532

./csolve --batch measurements.txt --depol-ratio-cons \
         --depol-ratio-mode rank                        # как в main
```

Одиночный режим — та же опция с `--data`:

```bash
./csolve --data input.json --depol-ratio-cons --depol-ratio-w 2 \
         --json out.json
```

Формат и разрешение графиков, тайминги фаз:

```bash
./csolve --data input.json --plot-font-size 12       # PDF, встроенный рендерер
./csolve --data input.json --plotting gnuplot --plot-format pdf --out result.pdf \
         --plot-dpi 300                              # gnuplot, DPI имеет смысл
CSOLVE_TIME=1 ./csolve --no-plot
```

Без `--tables` и `--type` используется встроенный набор `agglomerate`
(56 значений `m`, `x` до 82.7). Его таблицы ограничивают `r1_max` примерно
4.7 мкм на 355 нм, поэтому при больших радиусах нужны явные `--r1-min`/
`--r1-max` (см. [Ограничения](#ограничения-и-типичные-ошибки)).

## Режимы работы

1. **Одиночный режим** — один набор коэффициентов (`--data` или демо-данные).
   Результат печатается в консоль, при `--json` пишется JSON, при
   отсутствии `--no-plot` строится график.
2. **Пакетный режим** (`--batch <TXT>`) — набор профилей по высотам. Матрицы
   `A`, таблицы ядер и ядра `δ_l` строятся один раз на весь пакет; для каждой
   высоты пишутся `dist_<H>.txt` и общие по высоте файлы, строятся сводные
   графики. Опционально (`--lidar-ratio-cons`) решения по высотам
   согласуются по гладкости лидарного отношения `S = α/β`.
3. **Демо-режим** — если `--data` не задан, коэффициенты вычисляются прямой
   задачей по фиксированному двухмодальному распределению. Истинный `m`
   задаётся `--m-real`/`--m-imag` и привязывается к ближайшему значению из
   сетки таблиц. Шум измерений — `--noise` (относительный, гауссов) и
   `--seed`.

Измеренная деполяризация `δ_l` учитывается в обоих режимах при
`--depol-ratio-cons`: `--depol-ratio-mode func` (по умолчанию) добавляет
строку ограничения в функционал, `--depol-ratio-mode rank` — штраф при
ранжировании решений.

## Входные данные

### Таблицы сечений

Таблицы встроены в бинарник: три набора сжаты gzip (`data.txt.gz`) и
скомпилированы через `go:embed`. Встроенный набор выбирается флагом `--type`:

| `--type` | Каталог-источник | m-точек | Точек по `x` | Диапазон `x` |
|---|---|---|---|---|
| `sphere` | `bases/base_sph_25/average` | 286 (22 Re × 13 Im) | 41 | 0.0120–626 |
| `spheroid` | `bases/base_sphrd_25/average` | 286 (22 Re × 13 Im) | 41 | 0.0120–626 |
| `agglomerate` (по умолчанию) | `bases/large_aggl_100/average` | 56 (7 Re × 8 Im) | 100 | 0.024–82.7 |

Все таблицы набора содержат `Cext`, `Cback`, `S11`, `S22`, поэтому `δ_l`
считается по всем значениям `m`.

Внешние таблицы (не входящие в бинарник) задаются через `--tables <DIR>`;
этот флаг взаимоисключим с `--type`. Внутри `DIR` лежат подкаталоги вида

```
<DIR>/mre_<Re(m)>_mim_<Im(m)>/data.txt
```

Например:

```
bases/large_aggl_100/shape02/mre_1.45_mim_0.01680/data.txt
```

Сетка `m` формируется автоматически из имён подкаталогов (`mre_%.2f_mim_%.5f`),
сортируется по `(Re, Im)`. Каталоги без `data.txt` (`data.txt.gz`) и
дубликаты игнорируются. Если `--tables` указывает на каталог, содержащий
`average/` или `shapeNN/` (а не сами таблицы), программа подскажет
корректный путь.

Текстовые `data.txt` остаются источником правды: встроенные `.gz`
пересобираются командой `go generate ./bases` (`make generate`), а тест
сверяет их байт-в-байт с исходниками.

Формат `data.txt` — «mkbase / mkbase_spheres»: строка-заголовок с `#`,
содержащая имя `x` и имена нужных столбцов, затем числовые строки (ниже
приведено сокращённо):

```
# x Cext Cabs Cback Qext Qabs Qback S11 S22 n
0.01197679162 2.34963536927e-12 ... 1
```

Правила чтения:

- столбцы выбираются **по именам** из заголовка: `x`, `Cext`, `Cback`,
  `S11`, `S22`; порядок столбцов и наличие лишних (`Cabs`, `Qext`, `n`, …)
  роли не играют;
- нужен хотя бы один из `Cext`/`Cback`; для каналов `β` обязателен `Cback`,
  для `α` — `Cext`;
- `x` обязан строго возрастать, точек не меньше 3;
- `Cext`/`Cback` должны быть строго положительными и конечными;
- `S11`/`S22` необязательны и могут содержать `nan` — тогда `δ_l` по этой
  таблице не считается;
- при большом шаге по `x` (максимальный `Δx > 1`) печатается предупреждение:
  Mie-рябь может не разрешаться.

Ядра интерполируются кубическим сплайном `ln K` от `ln r`; вне диапазона
`[rMin, rMax]` значение зажимается. Для `Cext`/`Cback` выход `x` за пределы
таблицы — ошибка, если не задан `--table-extrapolate`.

### JSON с измерениями

`--data <FILE>`:

```json
{
  "m": { "real": 1.45, "imag": -0.005 },
  "backscatter": {
    "wavelengths_nm": [355, 532, 1064],
    "coefficients": [1.44428e-4, 1.04797e-4, 5.93246e-5]
  },
  "extinction": {
    "wavelengths_nm": [355, 532],
    "coefficients": [5.0491e-4, 3.01617e-4]
  },
  "depolarization": {
    "wavelengths_nm": [532],
    "coefficients": [18.3]
  }
}
```

| Ключ | Единицы | Назначение |
|---|---|---|
| `m.real`, `m.imag` | — | Информационная пара `m`: только строка отчёта «refractive index m (initial/true)», на восстановление не влияет |
| `backscatter` | `1/(m·sr)` | Каналы `β`: `wavelengths_nm[]` и `coefficients[]` |
| `extinction` | `1/m` | Каналы `α`: `wavelengths_nm[]` и `coefficients[]` |
| `depolarization` | `%` | Измеренные `δ_l` для `--depol-ratio-cons` |

Правила:

- хотя бы одна группа `backscatter`/`extinction` должна содержать каналы
  (не более 32 суммарно); `depolarization` сама по себе каналов не создаёт;
- длины волн — в **нанометрах**, коэффициенты `β`/`α` — в единицах таблицы;
- коэффициенты `backscatter`/`extinction` должны быть положительными;
- порядок каналов сохраняется: сначала `β` (`backscatter`), затем `α`
  (`extinction`); при несовпадении длин массивов берётся меньшая;
- `depolarization.wavelengths_nm` сопоставляются с 355 и 532 нм (другие —
  предупреждение и пропуск); значения — в процентах; без
  `--depol-ratio-cons` группа читается, но не используется; при отсутствии
  `S11`/`S22` в таблицах `δ_l` не считается;

### Пакетный TXT

`--batch <TXT>` — таблица измерений по высотам. Первая непустая строка —
заголовок, далее по строке на высоту.

| Столбец | Единицы | Обязательность |
|---|---|---|
| `Altitude` (также `alt`, `h`) | м | первое поле заголовка |
| `b<nm>` | `1/(m·sr)` | хотя бы один канал `β`/`α` |
| `a<nm>` | `1/m` | |
| `dep<nm>` | % | необязательно, для `--depol-ratio-cons` |

Пример:

```
Altitude b355 b532 a355 a532
500   1.44e-4 1.05e-4 5.05e-4 3.02e-4
700   1.50e-4 1.09e-4 5.20e-4 3.10e-4
900   1.57e-4 1.13e-4 5.35e-4 3.18e-4
```

- строки после заголовка: высота (м) и ровно столько значений, сколько
  столбцов в заголовке (без высоты); пустые строки и строки, начинающиеся
  с `#`, пропускаются;
- единицы коэффициентов те же: `β [1/(m·sr)]`, `α [1/m]`, `δ_l` — проценты;
- имена `b<nm>`/`a<nm>`/`dep<nm>` разбираются без учёта регистра, порядок
  столбцов произвольный; порядок каналов в отчётах — как в заголовке;
- дубликат `dep<nm>` с той же длиной волны — ошибка;
- `nan` допустим в любом столбце (для `dep` — «измерения нет»);
- общие длины волн (где есть и `β`, и `α`) используются для лидарного
  отношения `S = α/β`; для согласования по высоте нужны ≥ 2 высот;
- необязательные столбцы `dep<nm>` задают измеренное `δ_l` в **процентах**
  (сопоставляются с 355/532 нм) и нужны для `--depol-ratio-cons`:

  ```
  Altitude b355 b532 a355 a532 dep532
  500   1.44e-4 1.05e-4 5.05e-4 3.02e-4 12.5
  700   1.50e-4 1.09e-4 5.20e-4 3.10e-4 nan
  ```

  Без флага столбцы `dep<nm>` читаются, но игнорируются; с флагом
  отсутствие хотя бы одного такого столбца — ошибка. `nan` допустим и
  означает, что на этой высоте ограничение не применяется.

## Опции командной строки

Значения по умолчанию совпадают с C-версией, кроме `--degree`
(ровно одно значение) и блока деполяризации, которого в C-версии нет
(`--depol-ratio-*`, по умолчанию `--depol-ratio-mode func`).

### Общие

### Ограничения и обработка

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--nonneg` | выкл. | Ограничение `C ≥ 0` (NNLS, Lawson–Hanson) |
| `--no-zero-boundary` | выкл. | Без краевых условий `n(r0)=n(r1)=0` |
| `--no-smooth` | выкл. | Отключить сглаживание среднего |
| `--smooth-lam <X>` | `1e-4` | Параметр сглаживающего сплайна |
| `--r-split <X>` | `0.5` | Граница fine/coarse, мкм |
| `--modes auto`/`fit`/`stat` | `auto` | Метод параметров мод |
| `--absolute` | выкл. | МНК по абсолютным, а не относительным невязкам |
| `--depol-ratio-cons` | выкл. | Учёт измеренного `δ_l` (`dep<nm>` / `depolarization` в JSON) |
| `--depol-ratio-w <X>` | `1` | Вес ограничения `δ_l` (`≥ 0`) |
| `--depol-ratio-mode func`/`rank` | `func` | Способ учёта: в функционале или при ранжировании |

Ограничение `--depol-ratio-cons` работает в одиночном и пакетном режимах;
способ учёта задаёт `--depol-ratio-mode`:

- **`func`** (по умолчанию) — строка ограничения добавляется в
  МНК/NNLS-систему. Условие `δ_l = δ_m` точно сводится к линейному: при
  `r = δ_m/100` и `ρ = (1+r)/(1−r)`

  ```
  q·C = 0,   q_i = a11_i − ρ·a22_i,
  ```

  где `a11`/`a22` — проекции `S11`/`S22` на базис окна. Строка нормируется
  на `ρ·D22` канального решения того же варианта (то же `γ`, без
  ограничения), т.е. даёт относительную невязку `D11/D22`; вес —
  `--depol-ratio-w`. Для каждого варианта `(m, окно)` выполняется второй
  проход с этой строкой; `γ` по-прежнему выбирается по каналам.
- **`rank`** — решение не меняется; после перебора варианты сортируются по
  `Err + w·|δ_l − δ_l^meas|/δ_l^meas` (среднее по измеренным λ). При
  совместном `--lidar-ratio-cons` штрафы складываются в общем функционале
  ранжирования.

`Err` в отчётах остаётся канальным. При `--depol-ratio-w 0` ограничение
фактически отключено (результат совпадает с прогоном без флага).
Невалидные измерения (`nan`; `δ_l^meas ≤ 0` в режиме `rank`; `|δ_l| ≥ 100 %`
в режиме `func`) и несовпадающие длины волн игнорируются; при отсутствии
`S11`/`S22` печатается предупреждение.

## Алгоритм

1. **Таблицы и сетка `m`.** Читаются `mre_*_mim_*` подкаталоги, строится
   список `m`; для каждого `m` загружается `data.txt` (кэшируется).
2. **Покрытие.** Вычисляется `r_max = x_max·λ/(2π)` по каждому каналу;
   `r1_max` ограничивается минимумом по каналам и по всем `m`. Если
   `r1_min` больше — ошибка.
3. **Ядра.** На сетке `r` с шагом `dr = dx_max·λ_min/(2π)` строятся `K_j(r)`
   для всех `m`; интерполяция — кубический сплайн `ln K` от `ln r`.
4. **Базис.** Для каждого окна `[r0, r1]` и степени `p` строятся B-сплайны:
   `p+1` совпадающих узлов на каждом конце, `n_basis−p−1` внутренних
   геометрических узлов. При краевых условиях число неизвестных —
   `n_basis − 2`, иначе `n_basis`.
5. **Квадратура.** Гаусс–Лежандра порядка `quad_order` на подотрезках,
   ширина которых в `ln r` не превышает `log_span`.
6. **Матрицы `A`.** Для всех `(m, окно)` считаются
   `A[j,i] = Σ_q w_q K_j(r_q) q(r_q) B_i(r_q)`; спектральная норма
   `‖A‖₂` — через SVD.
7. **Обратная задача.** Для каждого варианта решается
   `[W A; γ L] c = [W g; 0]` (SVD-МНК через gonum или NNLS при `--nonneg`).
   `γ` задаётся `--gamma-rel·‖A‖₂` (fixed) либо выбирается на лог-сетке
   `[gamma-min, gamma-max]` по CV или по остаточной ошибке.
8. **Перебор и сортировка.** Варианты `(m, r0, r1, degree)` сортируются по
   средней относительной ошибке `Err`; берутся лучшие `G` (`--best`).
   При `--depol-ratio-cons --depol-ratio-mode func` в уравнение решения
   добавляется строка ограничения по измеренному `δ_l` (второй проход с
   тем же `γ`); в режиме `rank` к `Err` при сортировке добавляется штраф
   `w·|δ_l − δ_l^meas|/δ_l^meas`.
9. **Ансамбль.** Среднее считается только по решениям, чьё окно покрывает
   точку `r`; вне покрытия — `NaN`. Отдельно считается `m_avg`.
10. **Сглаживание.** Среднее сглаживается кубическим сглаживающим сплайном
    (эквивалент `scipy.interpolate.make_smoothing_spline`) с параметром
    `--smooth-lam`; в координатах `ln r` краевые веса усилены. Исходное
    среднее сохраняется как `n_avg_raw`.
11. **Моменты.** По покрытой области: `C_v = ∫ n dln r`,
    `N = ∫ n·(3/(4πr⁴)) dr`, `V̄ = C_v/N`, `r_eff = C_v / ∫ (n/r) dln r`,
    доля покрытия сетки.
12. **Моды.** Распределение делится на fine (`r ≤ r_split`) и coarse
    (`r ≥ r_split`), плюс overall. При `--modes fit`/`auto` выполняется
    МНК-фитинг логнормали в координатах `ln r` (веса ∝ √(числа
    покрывающих решений)); при неудаче или `--modes stat` — моментная
    оценка.
13. **Деполяризация.** Если в таблицах есть валидные `S11`/`S22`, на тех же
    узлах квадратуры считаются свёртки `S11(r)`, `S22(r)` с тем же средним
    распределением; результат `δ_l = (S11−S22)/(S11+S22)·100 %` на 355 и
    532 нм. При выходе `x` за диапазон таблицы значения зажимаются
    (печатается предупреждение).

Стоимость перебора — `nM · nW` решений; ядра и матрицы `A` считаются один
раз и переиспользуются (в пакетном режиме — на все высоты). `--best` < 1
приводится к 1; если вариантов меньше, используется столько, сколько есть.

## Единицы и соглашения

| Величина | Единицы |
|---|---|
| `β` (обратное рассеяние) | `1/(m·sr)` |
| `α` (ослабление) | `1/m` |
| Радиус `r`, `r0`, `r1`, `r_eff` | мкм |
| Длины волн (CLI, JSON, TXT) | нм |
| `dV/dln r` | µm³/cm³ |
| Концентрация `N` | cm⁻³ |
| Объёмы (`V`, `C_v`, `⟨V⟩`) | µm³/cm³, µm³ |
| `sigma` | безразмерный |
| `δ_l` | % |

Параметр размера `x = 2πr/λ` безразмерный; опорная длина волны таблиц по
умолчанию `λ_ref = 2π` мкм. Внутренние коэффициенты `C` размерные и
соответствуют `dV/dln r`.

## Тесты и проверка эквивалентности

Юнит-тесты (`make test`) не требуют внешних таблиц: встроенные наборы
проверяются на наличие и согласованность с `bases/`; остальные эталоны
получены из Python/scipy:

- not-a-knot сплайн (включая случай трёх точек);
- Гаусс–Лежандр и составная квадратура;
- B-сплайны (разбиение единицы, неотрицательность значений);
- ленточный Холецкий и NNLS (Lawson–Hanson);
- разбор таблиц (включая `S11`/`S22` и `nan`);
- встроенные наборы: 286/286/56 значений `m`, наличие
  `Cext`/`Cback`/`S11`/`S22`, диапазоны `x`;
- совпадение встроенных `data.txt.gz` с текстовыми исходниками `bases/`
  (защита от устаревшего `make generate`);
- ядра и формула `δ_l`, проекции `S11`/`S22` на базис, строку
  ограничения `δ_l` в функционале и штраф при ранжировании;
- разбор пакетного TXT со столбцами `dep<nm>` (включая `nan` и
  произвольный порядок столбцов);
- сглаживание (`λ = 1e-4` и `λ = 1`);
- разбор аргументов и проверки диапазонов (включая `--type`,
  `--depol-ratio-mode` и значения по умолчанию).

Сверка с C-бинарником — скрипты в `tests/`:

```bash
# одиночный режим: JSON
python3 tests/compare_json.py c.json go.json

# пакетный режим: каталоги результатов
python3 tests/compare_dirs.py ref_dir cur_dir

# генератор 7 высот для проверки ветки сглаживания опорного профиля
python3 tests/make_many_batch.py /tmp/many.txt
```

При портировании сверялись сценарии (таблицы берутся из C-репозитория):
`base/average`, `base_aggl/average`, `miedir` (`--table-cback 4pi`), вход
из JSON, `--gamma-select cv` и `err`, `--nonneg`, `--absolute`,
`--no-zero-boundary`, `--no-smooth`, `--modes stat`, степени
`--degree 1..4`, пакетные прогоны (2 и 7 высот, `--lidar-ratio-cons`). Численные поля совпадают с точностью `rtol = 1e-6`,
коэффициенты `C` — `1e-5`. Единственное отличие — выбранное `gamma` на
плоском участке CV-критерия (решения при этом идентичны). Блок
`depolarization` пишется только Go-версией, при сверке JSON его нужно
исключать.

## Ограничения и типичные ошибки

- **Mie-режим не поддерживается** — ядра берутся только из таблиц;
  демо-данные тоже считаются по таблицам.
- **Покрытие таблиц по `x`.** Если `r1_min` превышает `x_max·λ/(2π)`,
  программа завершится с ошибкой и предложит уменьшить `--r1-min`, выбрать
  другой `--type` или расширить таблицы. Для `Cext`/`Cback` выход `x` за
  диапазон — ошибка (кроме `--table-extrapolate`); для `S11`/`S22` — зажим
  с предупреждением, поэтому `δ_l` может быть смещена (нужна таблица шире).
- **Встроенные агрегаты (`--type=agglomerate`, по умолчанию).** Таблицы
  покрывают `x = 0.024–82.7` (100 точек), т.е. `r1_max` ограничен примерно
  **4.7 / 7.0 / 14 мкм** на 355 / 532 / 1064 нм. Если нужны большие радиусы,
  задайте `--r1-min`/`--r1-max` явно. Колонки `S11`/`S22` есть у всех 56
  таблиц, так что `δ_l` считается целиком.
- **Недоопределённая система.** Если неизвестных на окно больше числа
  каналов, печатается предупреждение: решение опирается в основном на
  регуляризацию.
- **Слишком крупный шаг таблицы** (`Δx > 1`) — предупреждение о
  неразрешённой Mie-ряби.
- **Нет `gnuplot`** — при `--plotting=gnuplot` графики пропускаются с
  предупреждением `failed to build plot ...`, расчёт продолжается; по
  умолчанию (`--plotting=internal`) gnuplot не нужен.
- **`--lidar-ratio-cons` вне пакетного режима** — игнорируется с
  предупреждением; в пакетном режиме нужны ≥ 2 высот и хотя бы одна общая
  длина волны `β∩α`.
- **`--depol-ratio-cons` без измеренного `δ_l`** — ошибка: нужен столбец
  `dep<nm>` в пакетном TXT (например, `dep532`) или группа
  `depolarization` в JSON, а в демо-режиме — `--data` (измерений нет).
  Если в таблицах нет валидных `S11`/`S22` или измеренная длина волны не
  совпадает с 355/532 нм, печатается предупреждение и ограничение не
  применяется. В режиме `func` пропускаются измерения с `nan` или
  `|δ_l| ≥ 100 %`, в режиме `rank` — с `nan` или `δ_l^meas ≤ 0`.
  По умолчанию включён режим `func`, поэтому для прежнего поведения
  (`main`) указывайте `--depol-ratio-mode rank`.
- **Ошибки формата таблиц** — «columns ... come from headers with different
  x positions», «x must be strictly increasing», «insufficient points
  (>= 3)», «cross sections must be > 0 and finite».
- **Демо-`m` отсутствует в сетке** — программа перечислит доступные
  `m`, из которых нужно выбрать `--m-real`/`--m-imag`.

Сообщения об ошибках печатаются как `error: ...` в `stderr`, код возврата —
`1`; `--help` завершает программу с кодом `0`.
