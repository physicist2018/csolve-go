# csolve-go

Версия **v2.0.0-rc0** · Go 1.24 · [сторонние компоненты и лицензии](#лицензии-и-сторонние-компоненты)

`csolve-go` восстанавливает распределение частиц по размерам
`n(r) = dV/dln r` из набора лидарных коэффициентов — обратного рассеяния `β`
и/или ослабления `α` — решая обратную задачу регуляризованным методом
наименьших квадратов с базисом из B-сплайнов.

Ядра задачи (сечения `Cext(x)` и `Cback(x)` как функции параметра размера
`x = 2πr/λ`) берутся из **внешних таблиц**, поэтому программа не выполняет
Mie-расчёт: спектр комплексного показателя преломления и форма частиц
«зашиты» в таблицы. Дополнительно, если в таблицах есть столбцы `S11`/`S22`,
считается линейная деполяризация обратного рассеяния `δ_l`.

Это порт табличного режима C-версии `csolve` на **Go 1.24**: численный
конвейер (сплайны, B-сплайны, квадратуры Гаусса–Лежандра, регуляризованный
МНК, перебор окон, ансамбль решений, сглаживание, моменты, модальный анализ)
повторяет C-версию, а линейная алгебра (SVD/МНК) выполнена через `gonum`.
Графики по умолчанию рисуются встроенным рендерером в PDF (чистый Go, без
внешних программ); прежняя отрисовка через **gnuplot** доступна по
`--plotting=gnuplot`.

## Возможности

- Восстановление `dV/dln r` и кумулятивного объёма `V(r)` по произвольному
  набору каналов `β`/`α` (до 32 каналов в JSON-входе), с единой моделью по
  всем каналам. По умолчанию — метод монотонных функций: `V(r)`
  восстанавливается по неотрицательным приращениям на бинах и монотонна,
  поэтому `n(r) ≥ 0` гарантировано; прежний сплайновый алгоритм доступен
  через `--method spline`. Опция `--kernel-order 1|2|3|4` позволяет решать
  задачу относительно `dN/dln r`, `dS/dln r`, `dV/dln r` или
  `d(r⁴N)/dln r` для повышения численной устойчивости; результат всегда
  пересчитывается обратно в `dV/dln r`.
- Четыре встроенных набора таблиц сечений
  (`--type=sphere|spheroid|agglomerate|agglomerate-cs`),
  сжатых и скомпилированных в бинарник; внешние таблицы — через `--tables`.
- Оценка комплексного показателя преломления `m = Re(m) + i·Im(m)` перебором
  доступных в таблицах значений.
- Автоматический выбор окна `[r0, r1]`, числа бинов (или степени B-сплайна)
  и параметра регуляризации `γ`.
- Ансамблевое усреднение лучших решений, сглаживание среднего,
  огибающие распределения (минимум/максимум по решениям), интегральные
  моменты (концентрации, `r_eff`) и логнормальные моды (fine/coarse/overall).
- Линейная деполяризация `δ_l` на всех длинах волн входных данных (длины
  волн каналов и измеренной деполяризации) — если в таблицах есть
  `S11`/`S22`; опциональный учёт измеренного `δ_l` в функционале или при
  ранжировании (`--depol-ratio-cons`).
- Спектральные зависимости `α(λ)`, `β(λ)`, `S(λ) = α/β` и `δ_l(λ)`: для
  каждого решения ансамбля на сетке длин волн (по таблицам сечений), со
  средним, огибающими (min/max) и отдельными графиками рядом с основным
  (`--no-spectra` — отключить).
- Пакетная обработка профилей по высотам, включая ограничение гладкости
  лидарного отношения `S = α/β` вдоль высоты.
- Вывод в консоль, JSON и текстовые файлы; графики — встроенным
  рендерером (PDF или PNG) либо через gnuplot (PNG/PDF/SVG).
- Web-интерфейс (`--gui`): локальный сервер в бинарнике, форма параметров,
  запуск решателя и просмотр результатов в браузере без внешних зависимостей.

## Физическая постановка

Для каждого канала `j` (длина волны `λ_j`, тип `β` или `α`) измеренный
коэффициент выражается через распределение по объёму:

```
g_j = ∫ K_j(r) · q(r) · n(r) dr,      q(r) = 3 / (4π r⁴)
```

где `n(r) = dV/dln r`, а ядро `K_j(r)` — сечение из таблицы, пересчитанное
на нужную длину волны:

```
K_j(r) = C(x) · 1e-12 · (λ_j / λ_ref)²,      x = 2πr / λ_j
```

- `C(x)` — `Cext` для канала `α` и `Cback` для канала `β`;
- `λ_ref` — длина волны, при которой построены таблицы
  (`--table-ref-lambda-um`, по умолчанию `2π` мкм);
- множитель `1e-12` переводит мкм² в м²;
- для таблиц в конвенции `Cback = 4π·dσ/dΩ` укажите `--table-cback 4pi`
  (тогда `Cback` делится на `4π`).

Из таблиц также берётся допустимый диапазон `x`; он ограничивает сверху
максимальный радиус `r_max = x_max·λ/(2π)` для каждого канала.

### Метод монотонных функций (`--method monotone`, по умолчанию)

Распределение `n(r) = dV/dln r` восстанавливается через монотонную функцию
— кумулятивный объём

```
V(r) = ∫_{r0}^{r} n(r′) dln r′   [µm³/cm³],   V(r0) = 0,   V не убывает
```

В координатах `t = ln r` каждый канал превращается в интеграл Стилтьеса по
монотонной функции:

```
g_j = ∫ φ_j(r) dV(r),      φ_j(r) = K_j(r)·3/(4πr³) > 0
```

Ядро `φ_j` положительно, поэтому `g_j` — «положительная смесь» приращений
`V`, а класс монотонных функций выпуклый. На окне `[r0, r1]` вводится
геометрическая сетка бинов `r0 = r⁰ < r¹ < … < r^N = r1` с `Δ_k = ln(r^k/r^{k−1})`
и неизвестными — приращениями объёма `v_k ≥ 0`:

```
n(r) = v_k/Δ_k  на бине k,      V(r^k) = v_1 + … + v_k
A[j,k] = (1/Δ_k) · ∫_{бина k} K_j(r) q(r) dr      (> 0)
g ≈ A·v
```

Задача решается как NNLS с регуляризацией гладкости приращений:

```
min_{v ≥ 0} ‖ W (A v − g) ‖² + γ² ‖ D v ‖²
```

где `W` — веса невязок, `D` — оператор порядка `--reg-order`
(`0` — `I`, `1` — первые разности, `2` — вторые разности). Неотрицательность
приращений гарантирует `n ≥ 0` и монотонность `V(r)` **по построению**
(в режиме `spline` ограничение `C ≥ 0` лишь опционально и действует на
коэффициенты, а не на функцию). Число бинов задаёт `--v-bins`; окна
`(m, r0, r1)` перебираются как и раньше, и результаты усредняются.

### Альтернатива: B-сплайны (`--method spline`)

Распределение раскладывается по B-сплайнам степени `p` на отрезке `[r0, r1]`
(по умолчанию с краевыми условиями `n(r0) = n(r1) = 0`), а коэффициенты
разложения находятся из регуляризованной системы

```
min ‖ W (A c − g) ‖² + γ² ‖ L c ‖²,
A[j,i] = ∫ K_j(r) q(r) B_i(r) dr,
```

где `L` — матрица вторых разностей (штраф за кривизну решения),
`W` — веса невязок. При `--depol-ratio-cons --depol-ratio-mode func` в
систему добавляется линейное ограничение по измеренному `δ_l` (см. раздел
опций); в режиме `rank` ограничение применяется при сортировке вариантов.
Все варианты `(m, r0, r1, degree)` перебираются, сортируются по средней
относительной ошибке `Err` и усредняются.

В обоих режимах кумулятивный объём `V(r)` выводится в консоль, JSON, файлы
пакетного режима и на график; в режиме `monotone` он монотонен.

### Порядок ядра (`--kernel-order`, численная устойчивость)

По умолчанию обратная задача решается относительно `dV/dln r`. Опция
`--kernel-order k` (по умолчанию `3`) позволяет решать её относительно
распределения `y_k = dX_k/dln r`, где `X_k` — момент `r^{e_k}` числа частиц:

| `k` | величина | `g_k(r) = y_k/(dN/dln r)` | вес в `A` | пересчёт в `dV/dln r` |
|---|---|---|---|---|
| `1` | `dN/dln r` | `1` | `1/r` | `(4π/3)·r³` |
| `2` | `dS/dln r` | `4π·r²` | `1/(4π·r³)` | `r/3` |
| `3` | `dV/dln r` | `(4π/3)·r³` | `3/(4π·r⁴)` | `1` |
| `4` | `d(r⁴N)/dln r` | `r⁴` | `1/r⁵` | `(4π/3)/r` |

Прямая модель `g_j = ∫ K_j(r)·n(r) dr` с `n(r) = dN/dr = y_k/(r·g_k)` даёт
матрицу `A[j,i] = ∫ K_j(r)·w_k(r)·B_i(r) dr` с `w_k = 1/(r·g_k)`; для `k = 3`
это прежнее `q(r) = 3/(4πr⁴)`. После решения и усреднения профиль
пересчитывается точкой: `dV/dln r = (g_3/g_k)·y_k` (сглаживание, моменты,
`V(r)`, `gFit`, `δ_l`, JSON и графики работают уже с `dV/dln r`).

Смена порядка меняет обусловленность и эффективную регуляризацию, поэтому
результаты для разных `k` могут отличаться; это инструмент для борьбы с
неустойчивостью, а не другая физическая модель. Для `--method monotone`
`v_bins` в JSON — приращения выбранного `y_k`; формула пересчёта в
приращения объёма приведена в поле `model.kernel_volume_conversion`.

После построения матриц `A` в консоль печатается отдельная строка с числом
обусловленности `A` по окнам: для каждого окна берётся максимум по `m`, затем
выводятся `min`/`median`/`max` по окнам и худшее окно. Это позволяет быстро
сравнить порядки `--kernel-order` по численной устойчивости.

## Требования и сборка

Требования:

- **Go 1.24** (модуль объявляет `go 1.24.0`);
- `gonum` (`gonum.org/v1/gonum`, подтягивается через `go.sum`), cgo не нужен;
- `gonum.org/v1/plot` — встроенный рендерер PDF (тоже чистый Go);
  шрифт DejaVu Sans (`codeberg.org/go-fonts/dejavu`) встроен в бинарник;
- **gnuplot** в `PATH` — только при `--plotting=gnuplot`; по умолчанию
  (`--plotting=internal`) gnuplot не требуется;
- интерактивному режиму (`--tui`) нужен терминал; `charmbracelet/huh`
  подтягивается через `go.mod`, внешних программ не требуется.

Сборка:

```bash
cd csolve-go
make                # -> ./csolve
make build-windows  # -> ./csolve.exe (Windows x86_64)
make test           # юнит-тесты (внешние таблицы не нужны)
make vet
make generate       # пересобрать .gz встроенных таблиц (после правки bases/)
make clean          # удалить бинарники
```

Напрямую:

```bash
go build -trimpath -o csolve ./cmd/csolve
go test ./...
```

Кросс-сборка под Windows с macOS/Linux:

```bash
GOOS=windows GOARCH=amd64 go build -trimpath -o csolve.exe ./cmd/csolve
```

На Windows:

```bat
go build -trimpath -o csolve.exe .\cmd\csolve
```

На Windows для отрисовки через `--plotting=gnuplot` (по умолчанию не
требуется) установите gnuplot 6.0.5: инсталлятор
[`gp605-win64-mingw.exe`](https://sourceforge.net/projects/gnuplot/files/gnuplot/6.0.5/gp605-win64-mingw.exe/download)
или архив
[`gp605-win64-mingw.7z`](https://sourceforge.net/projects/gnuplot/files/gnuplot/6.0.5/gp605-win64-mingw.7z/download);
добавьте каталог `bin` установки в `PATH`.

## Быстрый старт

Полная справка по флагам:

```bash
./csolve --help
```

Демонстрация на синтетических данных (входные коэффициенты считаются прямой
задачей по двум логнормальным модам; каналы `β` 355/532/1064 нм и `α`
355/532 нм) — если `--data` не указан. Таблицы встроены в бинарник, поэтому
`--tables` не обязателен:

```bash
./csolve --type=sphere --table-extrapolate \
         --r0-min 0.05 --r0-max 0.3 --r1-min 0.5 --r1-max 1.9 --no-plot
```

Восстановление по собственным измерениям из JSON с сохранением результата:

```bash
./csolve --data input.json --type=sphere --table-extrapolate \
         --r0-min 0.05 --r0-max 0.3 --r1-min 0.5 --r1-max 1.9 \
         --json out.json
```

Встроенный набор агрегатов — дополнительно считается `δ_l`
(здесь `δ_l ≈ 10.4 %`, `5.6 %` и `1.4 %` на 355/532/1064 нм):

```bash
./csolve --type=agglomerate --table-extrapolate \
         --r1-min 0.1 --r1-max 0.6 --no-plot
```

Предыдущий набор агрегатов (`x` по радиусу описанной окружности) доступен как
`agglomerate-cs` (здесь `δ_l ≈ 1.46 %`, `0.72 %` и `0.14 %` на 355/532/1064 нм):

```bash
./csolve --type=agglomerate-cs --table-extrapolate \
         --r1-min 0.1 --r1-max 0.6 --no-plot
```

Внешние таблицы (не входящие в бинарник) задаются через `--tables` — путь
указывает на каталог **с подкаталогами `mre_*`**:

```bash
./csolve --tables bases/large_aggl_100/shape02 --table-extrapolate \
         --r1-min 0.1 --r1-max 0.6 --no-plot
```

Прежний сплайновый алгоритм (в C-версии он основной): степень B-сплайна
задаётся `--degree` (ровно одно значение), число базисных функций — `--n-basis`:

```bash
./csolve --type=sphere --table-extrapolate --method spline \
         --degree 3 --no-plot
```

В методе монотонных функций (по умолчанию) разрешение задаёт `--v-bins`, а
сглаживание приращений — `--reg-order 0|1|2`:

```bash
./csolve --type=sphere --table-extrapolate --v-bins 16 --reg-order 1 --no-plot
```

Пакетная обработка по высотам с ограничением гладкости `S = α/β`:

```bash
./csolve --batch measurements.txt --batch-out-dir out_batch \
         --type=sphere --table-extrapolate \
         --r0-min 0.05 --r0-max 0.3 --r1-min 0.5 --r1-max 1.9 \
         --lidar-ratio-cons
```

Учёт измеренной деполяризации `δ_l` (столбец `dep<nm>` в TXT или группа
`depolarization` в JSON). Ограничение включено по умолчанию; способ учёта —
`--depol-ratio-mode` (`func` — строка в функционале, `rank` — штраф при
ранжировании, как в `main`):

```bash
./csolve --batch measurements.txt --batch-out-dir out_batch \
         --depol-ratio-cons --lidar-ratio-cons          # в TXT есть dep532

./csolve --batch measurements.txt --depol-ratio-cons \
         --depol-ratio-mode rank                        # как в main
```

Одиночный режим — та же опция с `--data`:

```bash
./csolve --data input.json --depol-ratio-cons --depol-ratio-w 2 \
         --json out.json
```

Формат и разрешение графиков, тайминги фаз:

```bash
./csolve --data input.json --plot-font-size 12       # PDF, встроенный рендерер
./csolve --data input.json --plotting gnuplot --plot-format pdf --out result.pdf \
         --plot-dpi 300                              # gnuplot, DPI имеет смысл
./csolve --data input.json --out-dir out --json res.json
                                                     # out/result.pdf и out/res.json
CSOLVE_TIME=1 ./csolve --no-plot
```

Интерактивный режим (форма на пресетах и со всеми параметрами; запуск —
дочерним процессом `csolve`):

```bash
./csolve --tui
```

Без `--tables` и `--type` используется встроенный набор `agglomerate`
(56 значений `m`, `x` до 27.5). Его таблицы ограничивают `r1_max` примерно
1.6 мкм на 355 нм, поэтому при больших радиусах нужны явные `--r1-min`/
`--r1-max` (см. [Ограничения](#ограничения-и-типичные-ошибки)).

## Режимы работы

1. **Одиночный режим** — один набор коэффициентов (`--data` или демо-данные).
   Результат печатается в консоль, при `--json` пишется JSON, при
   отсутствии `--no-plot` строится график.
2. **Пакетный режим** (`--batch <TXT>`) — набор профилей по высотам. Матрицы
   `A`, таблицы ядер и ядра `δ_l` строятся один раз на весь пакет; для каждой
   высоты пишутся `dist_<H>.txt` и общие по высоте файлы, строятся сводные
   графики. При `--report` сохраняется документ отчёта с логом, сводкой по
   высотам и графиками PNG. Опционально (`--lidar-ratio-cons`) решения по высотам
   согласуются по гладкости лидарного отношения `S = α/β`, а `--batch-thin`
   предварительно усредняет входные строки в окнах заданной ширины по высоте.
3. **Демо-режим** — если `--data` не задан, коэффициенты вычисляются прямой
   задачей по фиксированному двухмодальному распределению. Истинный `m`
   задаётся `--m-real`/`--m-imag` и привязывается к ближайшему значению из
   сетки таблиц. Шум измерений — `--noise` (относительный, гауссов) и
   `--seed`.
4. **Интерактивный режим** (`--tui`) — форма на `charmbracelet/huh` для
   одиночного, пакетного и демо-режимов (см. ниже).
5. **Графический режим** (`--gui`) — локальный веб-интерфейс: бинарник
   поднимает сервер на `127.0.0.1`, открывает браузер, решатель запускается
   дочерним процессом (см. ниже).

Измеренная деполяризация `δ_l` учитывается в обоих режимах при
`--depol-ratio-cons`: `--depol-ratio-mode func` (по умолчанию) добавляет
строку ограничения в функционал, `--depol-ratio-mode rank` — штраф при
ранжировании решений.

### Интерактивный режим (`--tui`)

Запускается отдельно, без других флагов:

```bash
./csolve --tui
```

Первый экран предлагает пресет — демо на сферах, демо на агрегатах,
одиночное восстановление из JSON, пакетный профиль из TXT или `Custom` — и
вопрос, показывать ли все параметры. Под списком выводится описание
выбранного пресета; пресеты демо можно запустить сразу, остальные всегда
открывают полную форму.

Полная форма повторяет CLI и сгруппирована по назначению:

| Страница | Содержимое |
|---|---|
| **Input data** | режим входа: демо, JSON или пакетный TXT |
| **Input data — JSON file** / **— batch profile** | выбор файла; страницы показываются по режиму; для пакета также задаётся окно усреднения по высоте (`--batch-thin`) |
| **Demo data** | истинные `m`, шум и зерно генератора (только демо) |
| **Cross-section tables** | источник таблиц, экстраполяция, `λ_ref`, соглашение `Cback` |
| **Basis and size grid** | степень и число базисных функций, порядок ядра (`--kernel-order`), сетки `r0`/`r1`, `--min-ratio`, `--best` |
| **Regularization** | правило выбора `γ` и его сетка |
| **Constraints and averaging** | `--nonneg`, граничные условия, сглаживание, `--r-split`, `--modes`, `--absolute` |
| **Numerics** | `--dx-max`, `--nr-out`, `--quad-order`, `--log-span` |
| **Depolarization** | ограничение по измеренному `δ_l` и его вес/режим |
| **Lidar ratio** | гладкость `S = α/β` (только пакет) |
| **Output** | каталог вывода, файлы графика и JSON, backend, формат, DPI, шрифт |
| **Summary** | эквивалентная CLI-команда, пути выходных файлов и подтверждение |

Страницы, не относящиеся к выбранному режиму, пропускаются; описания полей
указывают соответствующий флаг CLI, а зависящие от режима или backend
описания обновляются на лету (например, что формат и DPI игнорируются
встроенным рендерером).

Расчёт запускается дочерним процессом `csolve`: вывод, предупреждения и
ошибки видны как в CLI, а `Ctrl+C` прерывает долгий пакетный прогон. После
завершения показываются код возврата, команда и пути файлов; `r` —
повторить, `e` — изменить параметры, `p` — выбрать другой пресет, `q` —
выход. Значения формы проверяются тем же `solve.ParseArgs`, поэтому TUI и
CLI принимают одни и те же комбинации.

Список встроенных наборов таблиц в форме берётся из `solve.TableTypes()`,
а значения по умолчанию — из `solve.DefaultArgs()`, то есть не дублируются.

### Графический режим (`--gui`)

Запускается отдельно, без других флагов; браузер открывается автоматически:

```bash
./csolve --gui            # случайный порт, открыть браузер
./csolve --gui --no-open  # только напечатать URL (headless/SSH)
./csolve --gui --port 8080
```

Бинарник поднимает HTTP-сервер на `127.0.0.1`, весь интерфейс (HTML/CSS/JS)
встроен в него через `//go:embed` — внешних зависимостей, Node.js и сборки
фронтенда нет, `go.mod` не меняется. Интерфейс двуязычный (RU/EN),
режимы — демо, одиночный JSON и пакетный TXT, с пресетами и полной формой
параметров. Значения проверяются тем же `solve.ParseArgs`, что CLI/TUI,
в форме видна эквивалентная команда. Решатель запускается дочерним
процессом (тот же бинарник), лог стримится в браузер, долгий прогон можно
прервать кнопкой Cancel.

Результаты:

- одиночный/демо-режим — сводные карточки, таблицы каналов/мод/лучших
  решений, графики `result.png` и спектров, скачивание JSON/PNG/PDF/отчёта;
- пакетный режим — логи, сводные таблицы по высотам и все файлы результата
  (графики по высотам, `moments.txt`, `refractive.txt`, `errors.txt` и т.д.).

Входные файлы можно выбрать кнопкой «Обзор…» (серверный обозреватель
каталогов) или загрузить перетаскиванием. Сервер слушает только loopback и
защищён случайным токеном сессии; кнопка Quit (или Ctrl+C) останавливает его.

## Входные данные

### Таблицы сечений

Таблицы встроены в бинарник: четыре набора сжаты gzip (`data.txt.gz`) и
скомпилированы через `go:embed`. Встроенный набор выбирается флагом `--type`:

| `--type` | Каталог-источник | m-точек | Точек по `x` | Диапазон `x` |
|---|---|---|---|---|
| `sphere` | `bases/base_sph_25/average` | 286 (22 Re × 13 Im) | 41 | 0.0120–626 |
| `spheroid` | `bases/base_sphrd_25/average` | 286 (22 Re × 13 Im) | 41 | 0.0120–626 |
| `agglomerate` (по умолчанию) | `bases/large_aggl_100/average` | 56 (7 Re × 8 Im) | 100 | 0.0076–27.5 |
| `agglomerate-cs` | `bases/large_aggl_100_cs/average` | 56 (7 Re × 8 Im) | 100 | 0.024–82.7 |

В наборе `agglomerate` параметр размера `x` рассчитан по
**объёмно-эквивалентному (объёмному) радиусу** агрегата: `r` в `x = 2πr/λ` —
радиус сферы того же объёма, что и агрегат. В наборе `agglomerate-cs`
(предыдущие таблицы агрегатов) `x` рассчитан по **радиусу описанной
окружности**.

Все таблицы всех встроенных наборов содержат `Cext`, `Cback`, `S11`, `S22`,
поэтому `δ_l` считается по всем значениям `m`.

> **Важно: конвенция `Cback` у встроенных наборов разная.** Сферические
> наборы (`sphere`, `spheroid`) хранят `Cback` в конвенции `Cback = 4π·dσ/dΩ`
> (`Cback = 4π·S11`), а агрегатные (`agglomerate`, `agglomerate-cs`) — в
> конвенции `Cback = dσ/dΩ` (`Cback = S11`). По умолчанию действует
> `--table-cback dsigma`, поэтому для `--type sphere` и `--type spheroid`
> нужно явно указывать `--table-cback 4pi`, иначе ядро канала `β` окажется в
> `4π` раз больше. Для агрегатов (и `--type` по умолчанию) дефолт верный.

| `--type` | `Cback/S11` | Конвенция `Cback` | Флаг |
|---|---|---|---|
| `sphere` | `4π` (≈ 12.566) | `4π·dσ/dΩ` | `--table-cback 4pi` |
| `spheroid` | `4π` (≈ 12.566) | `4π·dσ/dΩ` | `--table-cback 4pi` |
| `agglomerate` | `1` | `dσ/dΩ` | `dsigma` (по умолчанию) |
| `agglomerate-cs` | `1` | `dσ/dΩ` | `dsigma` (по умолчанию) |

Внутри каждого набора столбцы самосогласованы: `Qext`/`Qabs`/`Qback =
C/(πx²)` и `S11 = Csca·P11(180°)/(4π)` (проверено по теории Ми и рэлеевскому
пределу `P11(180°) = 1.5`); в сферах `S11 = S22`, в агломератах — `S22 ≤ S11`.

Внешние таблицы (не входящие в бинарник) задаются через `--tables <DIR>`;
этот флаг взаимоисключим с `--type`. Внутри `DIR` лежат подкаталоги вида

```
<DIR>/mre_<Re(m)>_mim_<Im(m)>/data.txt
```

Например:

```
bases/large_aggl_100/shape02/mre_1.45_mim_0.01680/data.txt
```

Сетка `m` формируется автоматически из имён подкаталогов (`mre_%.2f_mim_%.5f`),
сортируется по `(Re, Im)`. Каталоги без `data.txt` (`data.txt.gz`) и
дубликаты игнорируются. Если `--tables` указывает на каталог, содержащий
`average/` или `shapeNN/` (а не сами таблицы), программа подскажет
корректный путь.

Текстовые `data.txt` остаются источником правды: встроенные `.gz`
пересобираются командой `go generate ./bases` (`make generate`), а тест
сверяет их байт-в-байт с исходниками.

Формат `data.txt` — «mkbase / mkbase_spheres»: строка-заголовок с `#`,
содержащая имя `x` и имена нужных столбцов, затем числовые строки (ниже
приведено сокращённо):

```
# x Cext Cabs Cback Qext Qabs Qback S11 S22 n
0.01197679162 2.34963536927e-12 ... 1
```

Правила чтения:

- столбцы выбираются **по именам** из заголовка: `x`, `Cext`, `Cback`,
  `S11`, `S22`; порядок столбцов и наличие лишних (`Cabs`, `Qext`, `n`, …)
  роли не играют;
- нужен хотя бы один из `Cext`/`Cback`; для каналов `β` обязателен `Cback`,
  для `α` — `Cext`;
- `x` обязан строго возрастать, точек не меньше 3;
- `Cext`/`Cback` должны быть строго положительными и конечными;
- `S11`/`S22` необязательны и могут содержать `nan` — тогда `δ_l` по этой
  таблице не считается;
- при большом шаге по `x` (максимальный `Δx > 1`) печатается предупреждение:
  Mie-рябь может не разрешаться.

Ядра интерполируются кубическим сплайном `ln K` от `ln r`; вне диапазона
`[rMin, rMax]` значение зажимается. Для `Cext`/`Cback` выход `x` за пределы
таблицы — ошибка, если не задан `--table-extrapolate`.

### JSON с измерениями

`--data <FILE>`:

```json
{
  "m": { "real": 1.45, "imag": -0.005 },
  "backscatter": {
    "wavelengths_nm": [355, 532, 1064],
    "coefficients": [1.44428e-4, 1.04797e-4, 5.93246e-5]
  },
  "extinction": {
    "wavelengths_nm": [355, 532],
    "coefficients": [5.0491e-4, 3.01617e-4]
  },
  "depolarization": {
    "wavelengths_nm": [532],
    "coefficients": [18.3]
  }
}
```

| Ключ | Единицы | Назначение |
|---|---|---|
| `m.real`, `m.imag` | — | Информационная пара `m`: только строка отчёта «refractive index m (initial/true)», на восстановление не влияет |
| `backscatter` | `1/(m·sr)` | Каналы `β`: `wavelengths_nm[]` и `coefficients[]` |
| `extinction` | `1/m` | Каналы `α`: `wavelengths_nm[]` и `coefficients[]` |
| `depolarization` | `%` | Измеренные `δ_l` для `--depol-ratio-cons` |

Правила:

- хотя бы одна группа `backscatter`/`extinction` должна содержать каналы
  (не более 32 суммарно); `depolarization` сама по себе каналов не создаёт;
- длины волн — в **нанометрах**, коэффициенты `β`/`α` — в единицах таблицы;
- коэффициенты `backscatter`/`extinction` должны быть положительными;
- порядок каналов сохраняется: сначала `β` (`backscatter`), затем `α`
  (`extinction`); при несовпадении длин массивов берётся меньшая;
- `depolarization.wavelengths_nm` сопоставляются с длинами волн, для которых
  считаются `S11`/`S22` (все длины волн каналов и самой измеренной
  деполяризации); несовпадающие — предупреждение и пропуск;
  значения — в процентах; без `--depol-ratio-cons` группа читается, но не
  используется; при отсутствии `S11`/`S22` в таблицах `δ_l` не считается;

### Пакетный TXT

`--batch <TXT>` — таблица измерений по высотам. Первая непустая строка —
заголовок, далее по строке на высоту.

| Столбец | Единицы | Обязательность |
|---|---|---|
| `Altitude` (также `alt`, `h`) | м | первое поле заголовка |
| `b<nm>` | `1/(m·sr)` | хотя бы один канал `β`/`α` |
| `a<nm>` | `1/m` | |
| `dep<nm>` | % | необязательно, для `--depol-ratio-cons` |

Пример:

```
Altitude b355 b532 a355 a532
500   1.44e-4 1.05e-4 5.05e-4 3.02e-4
700   1.50e-4 1.09e-4 5.20e-4 3.10e-4
900   1.57e-4 1.13e-4 5.35e-4 3.18e-4
```

- строки после заголовка: высота (м) и ровно столько значений, сколько
  столбцов в заголовке (без высоты); пустые строки и строки, начинающиеся
  с `#`, пропускаются;
- единицы коэффициентов те же: `β [1/(m·sr)]`, `α [1/m]`, `δ_l` — проценты;
- имена `b<nm>`/`a<nm>`/`dep<nm>` разбираются без учёта регистра, порядок
  столбцов произвольный; порядок каналов в отчётах — как в заголовке;
- дубликат `dep<nm>` с той же длиной волны — ошибка;
- `nan` допустим в любом столбце (для `dep` — «измерения нет»);
- общие длины волн (где есть и `β`, и `α`) используются для лидарного
  отношения `S = α/β`; для согласования по высоте нужны ≥ 2 высот;
- необязательные столбцы `dep<nm>` задают измеренное `δ_l` в **процентах**
  (сопоставляются с длинами волн каналов и столбцов `dep<nm>`, для которых
  считаются `S11`/`S22`) и нужны для `--depol-ratio-cons`:

  ```
  Altitude b355 b532 a355 a532 dep532
  500   1.44e-4 1.05e-4 5.05e-4 3.02e-4 12.5
  700   1.50e-4 1.09e-4 5.20e-4 3.10e-4 nan
  ```

  Без флага столбцы `dep<nm>` читаются, но игнорируются; с флагом
  отсутствие хотя бы одного такого столбца — ошибка. `nan` допустим и
  означает, что на этой высоте ограничение не применяется.

#### Прореживание по высоте (`--batch-thin`)

Флаг `--batch-thin <W>` включает усреднение входных строк по высоте до
восстановления. Задаётся окно `W` в метрах; `0` (по умолчанию) — прореживание
выключено.

По исходным высотам строятся окна ширины `W`:

```
hmin = min(Altitude), hmax = max(Altitude)
окно k: [hmin + k·W, hmin + (k+1)·W),  k = 0..N-1
N = max(1, ceil((hmax - hmin) / W))
```

Последнее окно обрезается по `hmax`. Строки, попавшие в окно, усредняются
по каждому столбцу (`β`, `α`, `dep<nm>`); высота результата — центр
фактического окна. `nan` при усреднении игнорируется: если в окне для
`dep<nm>` нет конечных значений, результат `nan`, а окно с неполными или
неположительными `β`/`α` пропускается с предупреждением. Результат
сортируется по возрастанию высоты. Если после прореживания не осталось
валидных окон — ошибка.

```bash
./csolve --batch measurements.txt --batch-thin 100 --batch-out-dir out_batch
```

В `dist_<H>.txt` добавляется комментарий с окном усреднения и числом
исходных строк.

## Опции командной строки

Значения по умолчанию совпадают с C-версией, кроме метода восстановления
(по умолчанию `--method monotone`, в C-версии — сплайны; прежнее поведение —
`--method spline`), `--degree` (ровно одно значение) и блока деполяризации,
которого в C-версии нет (`--depol-ratio-*`, по умолчанию
`--depol-ratio-mode func`).

### Общие

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-h`, `--help` | — | Справка по всем флагам и выход с кодом `0` |
| `--tui` | — | Интерактивный терминальный режим; принимается только один аргумент |
| `--gui` | — | Веб-интерфейс в браузере; должен быть первым аргументом. Свои флаги: `--port N` (0 = случайный), `--no-open` |

### Вход и таблицы

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--data <JSON>` | — | Измеренные коэффициенты; без флага — демо-данные |
| `--type {sphere\|spheroid\|agglomerate\|agglomerate-cs}` | `agglomerate` | Встроенный набор таблиц (в бинарнике) |
| `--tables <DIR>` | — | Внешний каталог с `mre_<real>_mim_<imag>/data.txt` (взаимоисключим с `--type`) |
| `--table-extrapolate` | выкл. | Разрешить экстраполяцию сечений по `x` |
| `--table-ref-lambda-um <X>` | `2π` (≈ 6.283) | Опорная длина волны таблиц, мкм |
| `--table-cback dsigma` или `4pi` | `dsigma` | Конвенция столбца `Cback`: для `--type sphere`/`spheroid` нужен `4pi` (`Cback = 4π·dσ/dΩ`), для агрегатов — `dsigma` |

### Метод, базис, окна и перебор

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--method monotone` или `spline` | `monotone` | Метод восстановления: монотонная `V(r)` по бинам или B-сплайны |
| `--v-bins <N>` | `0` (авто) | Число бинов на окно для `monotone`; `0` = `max(2·каналов, 8)`, не больше 64 |
| `--reg-order <0..2>` | `2` | Порядок штрафа за негладкость приращений (`monotone`) |
| `--degree <1..4>` | `1` | Степень B-сплайна (`spline`; ровно одно значение) |
| `--n-basis <N>` | `7` (`0` — по числу каналов) | Базисных функций на окно (`spline`) |
| `--kernel-order <1..4>` | `3` | Решать относительно `dN/dln r` (1), `dS/dln r` (2), `dV/dln r` (3) или `d(r⁴N)/dln r` (4); результат пересчитывается в `dV/dln r` |
| `--r0-min <X>` | `0.05` | Нижняя граница сетки `r0`, мкм (`> 0`) |
| `--r0-max <X>` | `0.3` | Верхняя граница сетки `r0`, мкм |
| `--nr0 <N>` | `7` | Число значений `r0` (геометрическая сетка) |
| `--r1-min <X>` | `0.45` | Нижняя граница сетки `r1`, мкм |
| `--r1-max <X>` | `3` | Верхняя граница сетки `r1`, мкм |
| `--nr1 <N>` | `7` | Число значений `r1` |
| `--min-ratio <X>` | `4` | Отбрасывать окна с `r1 < X·r0` |
| `--best <G>` | `0.05` | Лучших решений для ансамбля: целое — число; доля из `(0,1)` — от всех решений |

### Регуляризация

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--gamma-select fixed`/`cv`/`err` | `fixed` | Правило выбора `γ` |
| `--gamma-rel <X>` | `0.1` | `γ = rel·‖A‖₂` при `fixed` (≥ 0) |
| `--gamma-min <X>` | `-7` | Нижний `lg γ` при `cv`/`err` |
| `--gamma-max <X>` | `5` | Верхний `lg γ` при `cv`/`err` |
| `--ngamma <N>` | `41` | Число значений `γ` на лог-сетке |

`cv` — leave-one-out кросс-валидация, `err` — минимум относительной невязки.
При `--nonneg` для `cv` используется прямой пересчёт (NNLS).

### Ограничения и обработка

| Флаг | По умолчанию | Описание |
|---|---|---|
| `--nonneg` | вкл. | Ограничение `C ≥ 0` (NNLS, Lawson–Hanson); в режиме `monotone` включено всегда |
| `--no-nonneg` | — | Отключить ограничение `C ≥ 0` (только `--method spline`) |
| `--no-zero-boundary` | выкл. | Без краевых условий `n(r0)=n(r1)=0` (только `--method spline`; в `monotone` игнорируется) |
| `--no-smooth` | выкл. | Отключить сглаживание среднего |
| `--smooth-lam <X>` | `1e-4` | Параметр сглаживающего сплайна |
| `--r-split <X>` | `0.5` | Граница fine/coarse, мкм |
| `--modes auto`/`fit`/`stat` | `stat` | Метод параметров мод |
| `--absolute` | выкл. | МНК по абсолютным, а не относительным невязкам |
| `--depol-ratio-cons` | вкл. | Учёт измеренного `δ_l` (`dep<nm>` / `depolarization` в JSON) |
| `--no-depol-ratio-cons` | — | Отключить ограничение `δ_l` |
| `--depol-ratio-w <X>` | `1` | Вес ограничения `δ_l` (`≥ 0`) |
| `--depol-ratio-mode func`/`rank` | `func` | Способ учёта: в функционале или при ранжировании |

Ограничение `--depol-ratio-cons` включено по умолчанию и работает в
одиночном и пакетном режимах; способ учёта задаёт `--depol-ratio-mode`.

- **`func`** (по умолчанию) — строка ограничения добавляется в
  МНК/NNLS-систему. Условие `δ_l = δ_m` точно сводится к линейному: при
  `r = δ_m/100` и `ρ = (1+r)/(1−r)`

  ```
  q·C = 0,   q_i = a11_i − ρ·a22_i,
  ```

  где `a11`/`a22` — проекции `S11`/`S22` на базис окна. Строка нормируется
  на `ρ·D22` канального решения того же варианта (то же `γ`, без
  ограничения), т.е. даёт относительную невязку `D11/D22`; вес —
  `--depol-ratio-w`. Для каждого варианта `(m, окно)` выполняется второй
  проход с этой строкой; `γ` по-прежнему выбирается по каналам.
- **`rank`** — решение не меняется; после перебора варианты сортируются по
  `Err + w·|δ_l − δ_l^meas|/δ_l^meas` (среднее по измеренным λ). При
  совместном `--lidar-ratio-cons` штрафы складываются в общем функционале
  ранжирования.

`Err` в консольном отчёте — это средняя относительная невязка по каналам
и по измеренным `δ_l` (см. блок «Channel agreement»): валидные
измеренные `δ_l` входят в среднее наравне с каналами, а `nan`-измерения —
нет. Сам функционал подбора `γ` по-прежнему канальный. При
`--depol-ratio-w 0` ограничение фактически отключено (результат совпадает с
прогоном без флага).
Если измеренная поляризация отсутствует (демо-данные, JSON без группы
`depolarization`, batch без столбцов `dep<nm>`), ограничение по умолчанию
пропускается с предупреждением; явно заданный `--depol-ratio-cons` в этом
случае остаётся ошибкой. Отключить ограничение можно флагом
`--no-depol-ratio-cons`.
Невалидные измерения (`nan`; `δ_l^meas ≤ 0` в режиме `rank`; `|δ_l| ≥ 100 %`
в режиме `func`) и несовпадающие длины волн игнорируются; при отсутствии
`S11`/`S22` печатается предупреждение.

### Документ отчёта (`--report`)

`--report <FILE>` сохраняет консольный отчёт в документ по расширению:
`.docx` (Word) или `.odt` (OpenDocument). В одиночном режиме в документ
попадают:

- заголовок, дата и источник входных данных (`--data` или демо);
- весь текст отчёта, выведенный в терминал (моноширинный шрифт, отступы и
  пробелы сохраняются);
- основной график одиночного режима (три панели: `dV/dln r`, `V(r)` и
  сравнение коэффициентов) и отдельные графики спектров `α(λ)`, `β(λ)`,
  `S(λ)`, `δ_l(λ)` как изображения PNG — если графики и спектры не отключены
  (`--no-plot` / `--no-spectra`); картинки строятся выбранным backend'ом
  (`--plotting`): при `internal` — встроенным рендерером, при `gnuplot` —
  используются готовые PNG-файлы (`--plot-format png`) или те же графики
  перерисовываются gnuplot в PNG;
- раздел «Предупреждения» (`[warning]`), если они были (строки хронометража
  `[time]` не включаются).

Путь резолвится через `--out-dir`, как `--out`/`--json`.

В пакетном режиме документ дополнительно содержит:

- сводку по высотам тремя таблицами: микрофизика и оптика (`H`, `V`, `Vc`,
  `Vf`, `N`, `reff`, `Re(m)`, `Im(m)`, `Err`), параметры логнормальных мод
  (`rmf`, `rmc`, `rm`, `σf`, `σc`, `σ`) и, при наличии данных, линейную
  деполяризацию `δ_l` (расчётную и измеренную);
- сводные графики пакета (`refractive`, `error`, `volumes`, `radii`,
  `concentration`, `sigma`, `lidar_ratios`, `delpol` — при наличии);
- графики по каждой высоте: `plot_<H>` (распределение, `V(r)`, коэффициенты)
  и `spectrum_<H>` (спектры) — если они доступны и не отключены `--no-plot`
  (для спектров — также `--no-spectra`).

В пакетном режиме относительный путь резолвится через каталог результатов
пакета (`--batch-out-dir`, иначе `--out-dir`, иначе каталог TXT). Картинки
в отчёте строятся выбранным backend'ом: при `--plotting=gnuplot`
используются готовые PNG-файлы (`--plot-format png`) или те же графики
перерисовываются gnuplot в PNG.

Каждая таблица и каждый рисунок вставляются отдельным блоком: сначала сам
объект, затем на новой строке его название (подпись), затем разрыв страницы.
Последний объект завершающего разрыва не добавляет (если после него нет
предупреждений); при наличии раздела «Предупреждения» он начинается с новой
страницы.

| `dist_<H>.txt` | Комментарии (высота, входные коэффициенты) и колонки `r, dV/dln r, V`; далее `depol_calc_<wl>` (расчётная `δ_l`, `nan` без `S11`/`S22`) на всех длинах волн набора и `depol_meas_<wl>` (измеренная, для каждого столбца `dep<nm>`), затем `n_low`, `n_high` — огибающие распределения (µm³/cm³, до сглаживания); значения δ_l постоянны по строкам |
| `spectrum_<H>.txt` | Комментарии (высота, единицы, измеренные `a<nm>`/`b<nm>`/`S<nm>`/`dep<nm>`) и колонки `lambda_nm`, `alpha_mean alpha_low alpha_high`, `beta_mean beta_low beta_high`, `delta_mean delta_low delta_high`, `lidar_mean lidar_low lidar_high` (`nan` для недоступных величин; колонки `lidar_*` добавлены в конец, чтобы не сдвигать прежние); отсутствует при `--no-spectra` |
| `moments.txt` | `H Vf Vc V rmf rmc rm reff N sigma_f sigma_c sigma` |
| `refractive.txt` | `H Re(m) Im(m)` |
| `errors.txt` | `H` + относительные ошибки по каналам + `Err` (среднее) |
| `delpol.txt` | `H` + расчётные `delta_l_<wl>` на всех длинах волн каналов и `dep<nm>` (%, `nan` при отсутствии данных) + измеренные `delta_l_meas_<wl>` для каждого столбца `dep<nm>` |
| `lidar_ratios.txt` | `H` + `S_<wl>` — только при `--lidar-ratio-cons` и общих λ |
| `report.docx`/`report.odt` | Документ отчёта при `--report`: лог расчёта, сводка по высотам (таблицы) и графики PNG (сводные и по каждой высоте) |

Имена каналов в `errors.txt` берутся из заголовка TXT. Числа форматируются
как в C-версии (`%.6g`, `nan` в нижнем регистре), поэтому файлы численно
сопоставимы с выводом `csolve` на C.

### Графики

Способ отрисовки выбирается `--plotting`:

- `internal` (по умолчанию) — встроенный рендерер на `gonum.org/v1/plot`,
  пишет **PDF или PNG** средствами Go (без gnuplot и cgo), шрифт
  **DejaVu Sans** встроен в бинарник (латиница, греческий, кириллица,
  `µ`, `³`, `⁻`, `⟨⟩`);
- `gnuplot` — прежняя отрисовка через `gnuplot` в `PATH`, формат задаётся
  `--plot-format` (`png`/`pdf`/`svg`).

При `--plotting=internal` сочетание с `--plot-format svg` или с
`--out`, расширение которого не совпадает с форматом (`pdf`/`png`),
считается ошибкой; `--plot-dpi` не действует для векторного PDF
(предупреждение) и применяется к PNG. При сбое рендерера
печатается предупреждение, расчёт продолжается.

- Одиночный режим: многооконный график `result.<ext>` (по `--out`, путь
  разрешается относительно `--out-dir`): слева — распределение (истинное для
  демо, лучшие решения, огибающие `lower`/`upper` штриховыми, среднее
  сглаженное и до сглаживания), в центре — кумулятивный объём `V(r)`,
  справа — измеренные vs вычисленные коэффициенты.
  Рядом — отдельные графики спектров `result_alpha.<ext>`,
  `result_beta.<ext>`, `result_lidar.<ext>`, `result_depol.<ext>` (строятся,
  если величина доступна): тонкие серые кривые — индивидуальные решения,
  штриховые — огибающие, толстая — среднее, точки — измеренные входные
  данные. Для `S(λ)` измеренные точки появляются только на общих длинах
  волн, где есть и `α`, и `β`.
  На графиках `α(λ)` и `β(λ)` подписи тиков по оси ординат даются в
  научном виде, например `4.5×10⁻⁵` (показатель — надстрочный в обоих
  backend'ах).
- Пакетный режим: `plot_<H>.<ext>` на каждую высоту (распределение с
  огибающими по `G` лучшим решениям, `V(r)`, коэффициенты),
  `spectrum_<H>.<ext>` — сетка 2×2: в первом ряду `α(λ)` и `β(λ)`, во
  втором — `S(λ)` и `δ_l(λ)`, с одной общей легендой сверху, и сводные профили
  `refractive`, `error`, `volumes`, `radii`, `concentration`, `sigma`,
  `lidar_ratios` (при наличии), `delpol` (если есть конечные значения).
  На `delpol` расчётные серии `δ_l(λ)` рисуются сплошными линиями,
  измеренные `δ_l^{meas}(λ)` (при наличии столбцов `dep<nm>`) — штриховыми.
- Отличие встроенного рендерера: `refractive` рисуется двумя панелями
  (`Re(m)` и `Im(m)`) вместо двух осей X. Текст в PDF — настоящий Unicode
  (кириллица, греческий, `µ`, `³`, `⁻`, `⟨m⟩`) с ToUnicode-таблицей,
  шрифт сабсетится, поэтому файл занимает ~10–30 КБ.

## Алгоритм

1. **Таблицы и сетка `m`.** Читаются `mre_*_mim_*` подкаталоги, строится
   список `m`; для каждого `m` загружается `data.txt` (кэшируется).
2. **Покрытие.** Вычисляется `r_max = x_max·λ/(2π)` по каждому каналу;
   `r1_max` ограничивается минимумом по каналам и по всем `m`. Если
   `r1_min` больше — ошибка.
3. **Ядра.** На сетке `r` с шагом `dr = dx_max·λ_min/(2π)` строятся `K_j(r)`
   для всех `m`; интерполяция — кубический сплайн `ln K` от `ln r`.
4. **Параметризация решения.**
   - Порядок `--kernel-order` (по умолчанию `3`) задаёт распределение
     `y_k = dX_k/dln r`, относительно которого решается задача; в матрицу
     входит вес `w_k(r) = 1/(r·g_k(r))`, а итоговый профиль пересчитывается
     в `dV/dln r` множителем `g_3/g_k`. При `k = 3` это прежнее поведение.
   - `--method monotone` (по умолчанию): для каждого окна `[r0, r1]` строится
     геометрическая сетка из `N` бинов (`--v-bins`, `0` — авто
     `max(2·каналов, 8)`); неизвестные — приращения `y_k` `v_k ≥ 0`.
   - `--method spline`: для каждого окна `[r0, r1]` и степени `p` строятся
     B-сплайны: `p+1` совпадающих узлов на каждом конце, `n_basis−p−1`
     внутренних геометрических узлов. При краевых условиях число
     неизвестных — `n_basis − 2`, иначе `n_basis`.
5. **Квадратура.** Гаусс–Лежандра порядка `quad_order` на подотрезках,
   ширина которых в `ln r` не превышает `log_span` (для `monotone` — внутри
   каждого бина).
6. **Матрицы `A`.** Для всех `(m, окно)` считаются
   `A[j,i] = Σ_q w_q K_j(r_q) q(r_q) B_i(r_q)`; для бинов
   `B_k = 1/Δln r_k` на бине `k`, т. е. `A[j,k]` — среднее ядра по бину;
   спектральная норма `‖A‖₂` — через SVD.
7. **Обратная задача.** Для каждого варианта решается
   `[W A; γ D] c = [W g; 0]` (SVD-МНК через gonum или NNLS).
   В режиме `monotone` NNLS используется всегда (`v ≥ 0`), а `D` — строки
   порядка `--reg-order` (0 — `I`, 1 — первые, 2 — вторые разности).
   В режиме `spline` — `D` из вторых разностей, NNLS при `--nonneg`.
   `γ` задаётся `--gamma-rel·‖A‖₂` (fixed) либо выбирается на лог-сетке
   `[gamma-min, gamma-max]` по CV или по остаточной ошибке.
8. **Перебор и сортировка.** Варианты `(m, r0, r1)` (в `spline` — ещё и
   `degree`) сортируются по средней относительной ошибке `Err`; берутся
   лучшие `G` (`--best`). При `--depol-ratio-cons --depol-ratio-mode func`
   в уравнение решения добавляется строка ограничения по измеренному `δ_l`
   (второй проход с тем же `γ`); в режиме `rank` к `Err` при сортировке
   добавляется штраф `w·|δ_l − δ_l^meas|/δ_l^meas`.
9. **Ансамбль.** Среднее считается только по решениям, чьё окно покрывает
   точку `r`; вне покрытия — `NaN`. Так же считаются огибающие `lower`/`upper`
   (минимум/максимум по этим решениям, до сглаживания). Отдельно считается
   `m_avg`.
10. **Сглаживание.** Среднее сглаживается кубическим сглаживающим сплайном
    (эквивалент `scipy.interpolate.make_smoothing_spline`) с параметром
    `--smooth-lam`; в координатах `ln r` краевые веса усилены. Исходное
    среднее сохраняется как `n_avg_raw`. В режиме `monotone` отрицательные
    выбросы сглаживания зажимаются нулём, чтобы `n ≥ 0`.
11. **Кумулятивный объём.** `V(r) = ∫ n dln r′` считается по итоговому
    среднему `n` трапециями по `ln r`; поэтому `V(r_end) = C_v`, а в режиме
    `monotone` (где `n ≥ 0`) `V` не убывает.
12. **Моменты.** По покрытой области: `C_v = ∫ n dln r`,
    `N = ∫ n·(3/(4πr⁴)) dr`, `V̄ = C_v/N`, `r_eff = C_v / ∫ (n/r) dln r`,
    доля покрытия сетки.
13. **Моды.** Распределение делится на fine (`r ≤ r_split`) и coarse
    (`r ≥ r_split`), плюс overall. При `--modes fit`/`auto` выполняется
    МНК-фитинг логнормали в координатах `ln r` (веса ∝ √(числа
    покрывающих решений)); при неудаче или `--modes stat` — моментная
    оценка.
14. **Деполяризация.** Если в таблицах есть валидные `S11`/`S22`, на тех же
    узлах квадратуры считаются свёртки `S11(r)`, `S22(r)` с тем же средним
    распределением; результат `δ_l = (S11−S22)/(S11+S22)·100 %` на 355 и
    532 нм. При выходе `x` за диапазон таблицы значения зажимаются
    (печатается предупреждение).
15. **Спектры.** Для каждого из `G` лучших решений на сетке длин волн
    (по умолчанию — диапазон входных длин волн, `--spectrum-points` точек,
    плюс сами входные λ) считаются
    `α_t(λ) = ∫ K_ext q n_t dr`, `β_t(λ)` — то же с `Cback`,
    `S_t(λ) = α_t(λ)/β_t(λ)` (где `β_t > 0`), и
    `δ_t(λ) = (D11−D22)/(D11+D22)·100 %`; ядро —
    `K = µm²→m² · (λ/λ_ref)² · C(2πr/λ)`, `n_t` — `dV/dln r` решения `t`.
    Затем по ансамблю: `mean` — среднее, `low`/`high` — min/max. Если `x`
    выходит за диапазон таблицы, он зажимается (спектры диагностические и
    на восстановление не влияют); предупреждение — один раз на таблицу.

Стоимость перебора — `nM · nW` решений; ядра и матрицы `A` считаются один
раз и переиспользуются (в пакетном режиме — на все высоты). Значение `--best`
трактуется так: целое положительное — число решений для усреднения, значение
из `(0,1)` — доля всех найденных решений (`N = round(Ntot·best)`, не меньше 1).
Нецелое значение больше 1 округляется до ближайшего целого с предупреждением;
ноль и отрицательные значения недопустимы. Если вариантов меньше, используется
столько, сколько есть. Общее число решений и число усредняемых решений
печатаются в консоль по одному разу.

## Единицы и соглашения

| Величина | Единицы |
|---|---|
| `β` (обратное рассеяние) | `1/(m·sr)` |
| `α` (ослабление) | `1/m` |
| Радиус `r`, `r0`, `r1`, `r_eff` | мкм |
| Длины волн (CLI, JSON, TXT) | нм |
| `dV/dln r` | µm³/cm³ |
| Кумулятивный объём `V(r)` | µm³/cm³ |
| Концентрация `N` | cm⁻³ |
| Объёмы (`V`, `C_v`, `⟨V⟩`) | µm³/cm³, µm³ |
| `sigma` | безразмерный |
| `δ_l` | % |

Параметр размера `x = 2πr/λ` безразмерный; опорная длина волны таблиц по
умолчанию `λ_ref = 2π` мкм. В наборе `agglomerate` `r` —
объёмно-эквивалентный (объёмный) радиус агрегата, в `agglomerate-cs` —
радиус описанной окружности. Внутренние коэффициенты `C` (`spline`) и
`v_bins` (`monotone`) размерные и соответствуют `dV/dln r`; в `monotone`
`v_k` — объём бина в µm³/cm³. Бины равномерны по `ln r` между `r0` и `r1`.

При портировании сверялись сценарии с `--method spline` (таблицы берутся из
C-репозитория):
`base/average`, `base_aggl/average`, `miedir` (`--table-cback 4pi`), вход

## Ограничения и типичные ошибки

- **Mie-режим не поддерживается** — ядра берутся только из таблиц;
  демо-данные тоже считаются по таблицам.
- **Покрытие таблиц по `x`.** Если `r1_min` превышает `x_max·λ/(2π)`,
  программа завершится с ошибкой и предложит уменьшить `--r1-min`, выбрать
  другой `--type` или расширить таблицы. Для `Cext`/`Cback` выход `x` за
  диапазон — ошибка (кроме `--table-extrapolate`); для `S11`/`S22` — зажим
  с предупреждением, поэтому `δ_l` может быть смещена (нужна таблица шире).
- **Встроенные агрегаты (`--type=agglomerate`, по умолчанию).** Таблицы
  покрывают `x = 0.0076–27.5` (100 точек), т.е. `r1_max` ограничен примерно
  **1.6 / 2.3 / 4.7 мкм** на 355 / 532 / 1064 нм. Если нужны большие радиусы,
  задайте `--r1-min`/`--r1-max` явно. Параметр `x` здесь рассчитан по
  объёмно-эквивалентному (объёмному) радиусу агрегата. Колонки `S11`/`S22`
  есть у всех 56 таблиц, так что `δ_l` считается целиком.
- **Агрегаты CS (`--type=agglomerate-cs`).** Предыдущие таблицы агрегатов с
  `x` по радиусу описанной окружности: `x = 0.024–82.7` (100 точек), т.е.
  `r1_max` ограничен примерно **4.7 / 7.0 / 14 мкм** на 355 / 532 / 1064 нм.
  Диапазон `x` шире, чем у `agglomerate`, но радиусы соответствуют
  описанной окружности агрегата. Сетка по `x` на больших размерах крупная
  (max `Δx ≈ 6.5`), поэтому печатается предупреждение о неразрешённой
  Mie-ряби.
- **Конвенция `Cback` у `--type sphere` / `--type spheroid`.** Эти наборы
  хранят `Cback = 4π·dσ/dΩ` (`Cback/S11 = 4π`), в отличие от агрегатных, где
  `Cback = dσ/dΩ`. По умолчанию действует `--table-cback dsigma`, поэтому
  для сферических наборов обязательно задавайте `--table-cback 4pi` — иначе
  ядро канала `β` будет в `4π` раз больше и восстановление исказится.
- **`spheroid`: `S22 > S11` при больших `x`.** В наборе `base_sphrd_25` при
  `x ≳ 71` часть точек имеет `S22 > S11` (до `S22/S11 ≈ 1.22` при
  `x = 363.7`), т.е. `δ_l = (S11−S22)/(S11+S22) < 0` (до ≈ −9.9 %). Для
  ансамбля с зеркальной симметрией всегда `S22 ≤ S11`, поэтому в этой
  области `S22` — артефакт больших `x` (там же погрешность DLS-кернелов
  ~10 %) и `δ_l` доверять не стоит.
- **Число неизвестных.** В режиме `spline` при неизвестных больше числа
  каналов печатается предупреждение: решение опирается в основном на
  регуляризацию. В режиме `monotone` число бинов по умолчанию заведомо
  больше числа каналов (`max(2·каналов, 8)`) — это нормально, роль
  регуляризатора играет `--reg-order` вместе с `γ`.
- **Масса на краях окна.** В `monotone` нет краевых условий
  `n(r0)=n(r1)=0`, поэтому распределение может быть заметным у верхней
  границы окна (это физично, если мода лежит у предела покрытия таблиц).
  Если нужны занулённые края — используйте `--method spline`.
- **Отрицательное `dV/dln r`.** В `spline` сглаживание среднего может дать
  небольшие отрицательные значения; в `monotone` они зажимаются нулём,
  поскольку приращения `V` неотрицательны по построению.
- **Слишком крупный шаг таблицы** (`Δx > 1`) — предупреждение о
  неразрешённой Mie-ряби.
- **Нет `gnuplot`** — при `--plotting=gnuplot` графики пропускаются с
  предупреждением `failed to build plot ...`, расчёт продолжается; по
  умолчанию (`--plotting=internal`) gnuplot не нужен.
- **`--lidar-ratio-cons` вне пакетного режима** — игнорируется с
  предупреждением; в пакетном режиме нужны ≥ 2 высот и хотя бы одна общая
  длина волны `β∩α`.
- **`--batch-thin` вне пакетного режима** — игнорируется с предупреждением;
  слишком большое окно может свернуть профиль в одну высоту, после чего
  `--lidar-ratio-cons` не применяется (нужно ≥ 2 высот), а окна без валидных
  `β`/`α` пропускаются.
- **`--depol-ratio-cons` без измеренного `δ_l`** — ошибка: нужен столбец
  `dep<nm>` в пакетном TXT (например, `dep532`) или группа
  `depolarization` в JSON, а в демо-режиме — `--data` (измерений нет).
  Если в таблицах нет валидных `S11`/`S22` или измеренная длина волны не
  совпадает с длинами волн, для которых считаются `S11`/`S22`, печатается
  предупреждение и ограничение не применяется. В режиме `func` пропускаются
  измерения с `nan` или
  `|δ_l| ≥ 100 %`, в режиме `rank` — с `nan` или `δ_l^meas ≤ 0`.
  По умолчанию включён режим `func`, поэтому для прежнего поведения
  (`main`) указывайте `--depol-ratio-mode rank`.
- **Ошибки формата таблиц** — «columns ... come from headers with different
  x positions», «x must be strictly increasing», «insufficient points
  (>= 3)», «cross sections must be > 0 and finite».
- **Демо-`m` отсутствует в сетке** — программа перечислит доступные
  `m`, из которых нужно выбрать `--m-real`/`--m-imag`.

Сообщения об ошибках печатаются как `error: ...` в `stderr`, код возврата —
`1`; `--help` завершает программу с кодом `0`.
